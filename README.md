# 🎁 Вишлист — Telegram Mini App

Мини-приложение внутри Telegram-бота: пользователь собирает вишлист подарков
по ссылкам с любых магазинов, а друзья видят его вишлист и могут бронировать
подарки — незаметно для владельца.

## Что внутри

```
wishlist-app/
├── server/     Node.js: Telegram-бот + REST API + SQLite (один процесс)
└── webapp/     React Mini App (интерфейс, открывается внутри Telegram)
```

Это **один сервис**: `server` не только обслуживает API, но и раздаёт собранный
`webapp` как статику. Разворачивать нужно только `server` — фронтенд соберётся
в его же папку.

---

## Как это устроено (коротко)

- **Имя, фамилия, фото** — берутся из `Telegram.WebApp.initData`, когда пользователь
  открывает приложение.
- **О себе и дата рождения** — бот запрашивает их через метод Bot API `getChat`.
  ⚠️ Telegram отдаёт эти поля, **только если сам пользователь разрешил показывать
  их ботам** в Settings → Privacy and Security. Если человек это не включил —
  поля будут пустыми, это ограничение самого Telegram, обойти его нельзя.
- **Количество звёзд** — в Bot API нет метода «показать баланс звёзд пользователя»,
  поэтому реализовано как отдельная механика: гости могут нажать «Подарить звёзды»
  на чужом вишлисте, оплата проходит через настоящий Telegram Stars-платёж (валюта
  `XTR`), и звёзды копятся у владельца в базе — видно только ему самому.
- **Бронирование** — хранится в отдельной таблице `bookings`. Владельцу вишлиста
  API **никогда** не возвращает данные о бронях (даже поле не приходит), поэтому
  скрыть это на фронтенде физически невозможно — оно скрыто уже на сервере.
- **Красивая ссылка** — вида `https://t.me/ваш_бот/wishlist?startapp=u123456789`.
  Такую ссылку можно вставить в био профиля Telegram, отправить в чат или
  разместить где угодно — при переходе сразу открывается нужный вишлист.
  Показать Mini App прямо *внутри* нативного профиля пользователя Telegram не
  позволяет ни один сторонний бот — эта возможность зарезервирована для
  официальных функций Telegram (подарки, каналы). Ссылка — рабочая замена.

## Шаг 1. Создать бота и Mini App в @BotFather

1. Напишите **@BotFather** → `/newbot`, получите `BOT_TOKEN`.
2. `/mybots` → выберите бота → **Bot Settings → Mini App → Create/Configure**.
   - Укажите **тот же HTTPS-домен**, на котором будет жить `server` после деплоя
     (например `https://mywishlist.up.railway.app`).
   - Задайте **короткое имя** приложения, например `wishlist` — это и есть
     `WEBAPP_SHORT_NAME` / `VITE_WEBAPP_SHORT_NAME`.
3. (Необязательно) `/setmenubutton` — тоже можно настроить, но бот сам выставит
   кнопку меню автоматически при `/start`.

---

## Шаг 2. Настроить и собрать проект локально

```bash
# бэкенд
cd server
cp .env.example .env
# впишите BOT_TOKEN и (после шага 3) PUBLIC_URL
npm install

# фронтенд
cd ../webapp
cp .env.example .env
# впишите VITE_BOT_USERNAME и VITE_WEBAPP_SHORT_NAME
npm install
npm run build     # соберёт webapp/dist — его раздаёт server
```

Локальная разработка (без реального HTTPS-домена):

```bash
# терминал 1
cd server && USE_WEBHOOK=false npm run dev

# терминал 2
cd webapp && npm run dev
```

Для теста Mini App локально понадобится туннель (например `ngrok http 5173`
для фронтенда при разработке, либо `ngrok http 3000` для собранной версии) —
Telegram открывает Mini App только по HTTPS.

## Вариант деплоя: фронт на Vercel, бэкенд на Railway/Render

Это удобная комбинация: Vercel отлично раздаёт статику и подхватывает git-пуши
автоматически, а `server` (боту нужен постоянно работающий процесс и диск для
SQLite) уезжает на Railway/Render/VPS.

**1. Залейте `wishlist-app` в репозиторий на GitHub** (обычный `git init`, `git add`,
`git commit`, `git push` — ничего специфичного для этого проекта не требуется).

**2. Бэкенд (`server`) → Railway/Render**, как описано в Шаге 3 ниже. Получите
его публичный HTTPS-адрес, например `https://your-server.up.railway.app`.

**3. Фронтенд (`webapp`) → Vercel:**
   - New Project → импортируйте репозиторий → **Root Directory: `webapp`**
     (Vercel сам подхватит `vercel.json` внутри).
   - Environment Variables:
     - `VITE_BOT_USERNAME` = username бота без `@`
     - `VITE_WEBAPP_SHORT_NAME` = короткое имя из BotFather (например `wishlist`)
     - `VITE_API_BASE_URL` = адрес бэкенда с шага 2, **без слэша в конце**
       (например `https://your-server.up.railway.app`)
   - Deploy. Получите домен вида `https://your-app.vercel.app`.

**4. На бэкенде (Railway) добавьте переменную:**
   - `ALLOWED_ORIGIN` = `https://your-app.vercel.app` (домен из шага 3) — чтобы
     CORS пускал запросы только с вашего фронтенда.
   - `PUBLIC_URL` при этом остаётся адресом **самого бэкенда** (он нужен для
     вебхука бота), а не адресом Vercel.

**5. В @BotFather** укажите Mini App домен = **домен Vercel** (`your-app.vercel.app`),
не бэкенда — именно этот адрес Telegram будет открывать как приложение.

**6. Перезапустите бэкенд**, чтобы подхватить `ALLOWED_ORIGIN`, и напишите боту
`/start` — кнопка откроет Mini App с Vercel, а она уже сама обратится к API на Railway.

> Обратите внимание: в этом варианте статику из `webapp/dist`, которую раздаёт
> `server/src/index.js` по умолчанию, вы больше не используете — её заменяет
> Vercel. Это не мешает, просто лишний код, можно оставить как есть.

## Шаг 3. Задеплоить `server` на хостинг

Подойдёт любой хостинг с Node.js и постоянным диском для SQLite (Railway,
Render, обычный VPS). Пример для **Railway**:

1. Залейте папку `wishlist-app` в свой git-репозиторий.
2. В Railway создайте проект → **Deploy from repo**, укажите root directory `server`.
3. Перед деплоем выполните `npm run build` в `webapp` и закоммитьте `webapp/dist`
   (либо настройте отдельный build-step, который сначала собирает `webapp`,
   потом стартует `server`).
4. Задайте переменные окружения из `server/.env.example`:
   - `BOT_TOKEN`
   - `PUBLIC_URL` = выданный Railway HTTPS-домен
   - `USE_WEBHOOK=true`
   - `WEBAPP_SHORT_NAME`, `WEBHOOK_SECRET`, `DB_PATH` (например `/data/wishlist.db`,
     подключив persistent volume на `/data`)
5. Задеплойте. При старте сервер сам вызовет `setWebhook`.
6. В @BotFather ещё раз проверьте, что домен Mini App совпадает с `PUBLIC_URL`.

Готово — напишите боту `/start`, он откроет кнопку **«🎁 Открыть вишлист»**.

## Ограничения, о которых стоит помнить

| Что | Ограничение |
|---|---|
| Био и дата рождения | Видны, только если пользователь сам разрешил доступ ботам |
| Баланс звёзд | Нельзя прочитать существующий баланс — только звёзды, подаренные через это приложение |
| Распознавание цены по ссылке | Работает по `og:meta`-тегам страницы; часть сайтов (например с сильной защитой от ботов) может не отдавать корректные данные — тогда владелец может поправить карточку вручную |
| Виджет в самом профиле Telegram | Технически недоступно сторонним ботам — используйте ссылку `t.me/бот/wishlist?startapp=...` |

## Возможные доработки

- Кнопка «поделиться» через `switchInlineQuery`, чтобы отправлять вишлист прямо в любой чат из списка контактов.
- Уведомление владельцу, когда все подарки разобраны (без раскрытия, кто именно забронировал).
- Сортировка/приоритет подарков (поле `position` в БД уже есть).
