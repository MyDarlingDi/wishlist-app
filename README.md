# 🎁 Вишлист — Telegram Mini App

Мини-приложение внутри Telegram-бота: пользователь собирает вишлист подарков
по ссылкам с любых магазинов, а друзья видят его вишлист и могут бронировать
подарки — незаметно для владельца.

Инструкция ниже собрана под **полностью бесплатный** стек, без банковской карты:

- **Turso** — бесплатная облачная база данных (SQLite-совместимая)
- **Render** — бесплатный хостинг для бота и API (`server`)
- **Vercel** — бесплатный хостинг для интерфейса (`webapp`)
- **GitHub** — хранит код, оба хостинга деплоят прямо из репозитория

## Что внутри

```
wishlist-app/
├── server/     Node.js: Telegram-бот + REST API (Express + grammY)
└── webapp/     React Mini App (интерфейс, открывается внутри Telegram)
```

## Как это устроено (коротко)

- **Имя, фамилия, фото** — берутся из `Telegram.WebApp.initData`, когда пользователь
  открывает приложение.
- **О себе и дата рождения** — бот запрашивает их через метод Bot API `getChat`.
  ⚠️ Telegram отдаёт эти поля, **только если сам пользователь разрешил показывать
  их ботам** в Settings → Privacy and Security. Если человек это не включил —
  поля будут пустыми, это ограничение самого Telegram, обойти его нельзя.
- **Количество звёзд** — в Bot API нет метода «показать баланс звёзд пользователя»,
  поэтому реализовано как отдельная механика: гости могут нажать «Подарить звёзды»
  на чужом вишлисте, оплата проходит через настоящий Telegram Stars-платёж (валюта
  `XTR`), и звёзды копятся у владельца в базе — видно только ему самому.
- **Бронирование** — хранится в отдельной таблице `bookings`. Владельцу вишлиста
  API **никогда** не возвращает данные о бронях (даже поле не приходит), поэтому
  скрыть это на фронтенде физически невозможно — оно скрыто уже на сервере.
- **Красивая ссылка** — вида `https://t.me/ваш_бот/wishlist?startapp=u123456789`.
  Такую ссылку можно вставить в био профиля Telegram, отправить в чат или
  разместить где угодно — при переходе сразу открывается нужный вишлист.
  Показать Mini App прямо *внутри* нативного профиля пользователя Telegram не
  позволяет ни один сторонний бот — эта возможность зарезервирована для
  официальных функций Telegram (подарки, каналы). Ссылка — рабочая замена.

⚠️ У бесплатного Render есть особенность: сервис «засыпает» после ~15 минут
без запросов и просыпается около 30–50 секунд при следующем обращении. Для
личного/семейного использования это не критично — просто первое открытие
после паузы будет чуть медленнее.

## Шаг 1. Создать бота в Telegram

1. Откройте Telegram, найдите **@BotFather**.
2. Отправьте `/newbot`, придумайте имя и username (должен заканчиваться на `bot`).
3. Сохраните присланный **токен** вида `123456:AAExample` — понадобится в Шаге 4.
4. Отправьте `/mybots` → выберите бота → **Bot Settings → Mini App → Create Mini App**.
5. Задайте короткое имя, например `wishlist` (латиницей, без пробелов).
6. Домен пока не указывайте — вернёмся к этому в Шаге 6.

---

## Шаг 2. Создать бесплатную базу данных на Turso

1. Зайдите на **turso.tech** → Sign Up (можно через GitHub).
2. В дашборде нажмите **Create Database**, дайте любое имя (например `wishlist`),
   выберите ближайший регион → Create.
3. На странице базы найдите:
   - **Database URL** — вид `libsql://wishlist-ваш-логин.turso.io`
   - Нажмите **Create Token** → скопируйте **Auth Token**
4. Сохраните оба значения — понадобятся в Шаге 4.

---

## Шаг 3. Залить проект на GitHub

В папке `wishlist-app` (распакованный архив):
```bash
git init
git add .
git commit -m "Первая версия вишлиста"
```
На github.com создайте пустой репозиторий (без README), затем:
```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/НАЗВАНИЕ_РЕПО.git
git branch -M main
git push -u origin main
```

## Шаг 4. Задеплоить бэкенд (`server`) на Render

1. Зайдите на **render.com** → войдите через GitHub.
2. **New → Web Service** → выберите свой репозиторий.
   - Если Render не видит репозиторий: **Settings аккаунта Render → GitHub →
     Configure** → выдайте доступ нужному репозиторию (или всем репозиториям).
3. Настройки сервиса:
   - **Root Directory**: `server`
   - **Runtime**: Node
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free
4. В разделе **Environment** добавьте переменные:
   - `BOT_TOKEN` — токен из Шага 1
   - `USE_WEBHOOK` = `true`
   - `WEBHOOK_SECRET` — любая случайная строка
   - `WEBAPP_SHORT_NAME` = `wishlist`
   - `TURSO_DATABASE_URL` — из Шага 2
   - `TURSO_AUTH_TOKEN` — из Шага 2
   - `PUBLIC_URL` — пока оставьте пустым
5. Нажмите **Create Web Service**, дождитесь первого деплоя. Render выдаст
   домен вида `https://your-server.onrender.com`.
6. Вернитесь в **Environment**, впишите `PUBLIC_URL` = этот домен (без слэша
   в конце) → Save (сервис передеплоится и установит вебхук бота).
7. Проверьте в **Logs**, что есть строка `Webhook установлен`.

---

## Шаг 5. Задеплоить фронтенд (`webapp`) на Vercel

1. Зайдите на **vercel.com** → войдите через GitHub → **Add New → Project**.
2. Выберите тот же репозиторий, укажите **Root Directory**: `webapp`
   (Vercel сам подхватит `vercel.json`).
3. В **Environment Variables** добавьте:
   - `VITE_BOT_USERNAME` — username бота без `@`
   - `VITE_WEBAPP_SHORT_NAME` = `wishlist`
   - `VITE_API_BASE_URL` — домен из Шага 4.6 (без слэша в конце)
4. **Deploy**. Получите домен вида `https://your-app.vercel.app`.

---

## Шаг 6. Связать бэкенд и фронтенд

1. В Render → **Environment** добавьте:
   - `ALLOWED_ORIGIN` = домен из Шага 5 (`https://your-app.vercel.app`)
2. Save — сервис перезапустится с этой настройкой.

---

## Шаг 7. Указать домен Mini App в BotFather

1. **@BotFather** → `/mybots` → ваш бот → **Bot Settings → Mini App → Edit Mini App URL**.
2. Впишите домен **Vercel** из Шага 5 (не Render!): `https://your-app.vercel.app`.

---

## Шаг 8. Проверить

1. Откройте бота в Telegram → `/start` → кнопка **«🎁 Открыть вишлист»**.
2. Добавьте подарок по ссылке (кнопка «+»).
3. Скопируйте ссылку на вишлист и откройте её с другого аккаунта — проверьте,
   что бронирование работает и не видно владельцу.

## Локальная разработка (необязательно)

Для базы можно использовать локальный файл вместо Turso — просто укажите:
```
TURSO_DATABASE_URL=file:./data/wishlist.db
```
(без `TURSO_AUTH_TOKEN`). Дальше:
```bash
cd server && cp .env.example .env && npm install && USE_WEBHOOK=false npm run dev
cd ../webapp && cp .env.example .env && npm install && npm run dev
```
Для теста Mini App локально понадобится HTTPS-туннель (например `ngrok`),
так как Telegram открывает Mini App только по HTTPS.

## Ограничения, о которых стоит помнить

| Что | Ограничение |
|---|---|
| Био и дата рождения | Видны, только если пользователь сам разрешил доступ ботам |
| Баланс звёзд | Нельзя прочитать существующий баланс — только звёзды, подаренные через это приложение |
| Распознавание цены по ссылке | Работает по `og:meta`-тегам страницы; часть сайтов может не отдавать корректные данные — тогда владелец может поправить карточку вручную |
| Виджет в самом профиле Telegram | Технически недоступно сторонним ботам — используйте ссылку `t.me/бот/wishlist?startapp=...` |
| Render Free | Сервис «засыпает» без активности, первый запрос после паузы медленнее |

## Возможные доработки

- Кнопка «поделиться» через `switchInlineQuery`, чтобы отправлять вишлист прямо в любой чат.
- Уведомление владельцу, когда все подарки разобраны (без раскрытия, кто именно забронировал).
- Сортировка/приоритет подарков (поле `position` в БД уже есть).
